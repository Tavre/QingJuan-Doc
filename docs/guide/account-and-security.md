# 账号与安全

v2.0.0 为 Linux 远程后端加入独立账号体系。每位用户拥有自己的书架、阅读进度、下载任务和翻译任务；书源、解析器、翻译模型等服务级配置仍由管理员统一维护。

::: info Windows 本机模式
Windows 本机后端继续使用隐式管理员身份，无需注册、登录或连接 Token，也不会显示 GitHub 登录和两步验证入口。本页只适用于 Windows 远程模式与 Android。
:::

## 注册与登录

连接 Linux 后端后，打开 **我的**：

1. 新用户选择 **注册**，填写唯一邮箱、用户名和密码；
2. 根据服务器策略填写邮箱验证码、固定身份牌，或同时填写两者；
3. 已有用户使用用户名和密码登录；管理员启用 GitHub 登录后，也可使用已绑定的 GitHub 账号登录；
4. 启用两步验证的账号还需输入验证器动态码或一个恢复码。

注册页面会读取管理员当前设置。策略读取失败时不会提交注册；重新进入注册页会刷新策略。邮箱验证码、身份牌和密码只保留在当前表单中，切换后端、注册完成或返回登录后会被清除。

内置 `admin` 用户由升级或安装流程保留。它既是 Linux 客户端账号，也是唯一不能被停用或降权的管理员账号；浏览器管理界面仍使用另一套独立管理密码。

## 独立书架与权限

Linux 多用户模式中：

- 书架、阅读进度、下载与翻译任务按当前账号隔离；
- 番茄、起点等用户登录态按青卷账号隔离；
- 普通用户可以使用管理员已启用的书源、解析器和翻译服务；
- 只有管理员可以修改书源、解析器开关、模型设置等全服配置；
- Bika 凭据属于管理员维护的全服抓取配置，不作为个人账号数据保存。

同一个青卷账号在 Windows 与 Android 登录后可访问同一份远程书架。不同账号即使连接地址和连接 Token 相同，也不会互相看到书架或任务。

## 绑定 GitHub

管理员启用 GitHub Device Flow 后，已登录用户可在 **我的 → 账号安全** 中绑定 GitHub：

1. 确认当前账号密码；
2. 按界面提示打开 `https://github.com/login/device`；
3. 输入设备码并在 GitHub 完成授权；
4. 返回青卷等待绑定完成。

GitHub 只用于登录已经存在并主动绑定的青卷账号，不会自动注册账号，也不会申请邮箱或仓库权限。解绑后应改用本地用户名和密码登录。

## 开启两步验证

在 **我的 → 账号安全 → 两步验证（2FA）** 中：

1. 输入当前密码；
2. 用支持 TOTP 的验证器扫描二维码或录入密钥；
3. 输入 6 位动态验证码确认；
4. 立即复制并离线保存生成的 10 个恢复码。

动态码每 30 秒更新。恢复码只显示一次且每个只能使用一次；重新生成后，旧恢复码立即失效。密码登录和 GitHub 登录都必须完成第二步验证后才会建立会话。

::: warning 保存恢复码
不要把 TOTP 密钥、动态码或恢复码放入截图、聊天记录和普通云笔记。丢失验证器且没有可用恢复码时，需要联系服务器管理员重置账号安全状态。
:::

## 会话失效

修改密码、账号角色、启停状态、GitHub 绑定或两步验证设置后，旧用户会话会立即失效。客户端会返回登录入口；重新登录前不会加载上一账号的书架和任务。

切换 Linux 服务器时，旧服务器的用户会话也会清除。连接 Token 只允许进入指定服务器，不能替代用户名、密码或用户会话。
