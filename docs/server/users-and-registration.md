# 用户与注册

v2.0.0 的 Linux 后端支持多用户。浏览器管理界面的 **用户管理** 和 **注册设置** 用于维护账号、注册条件与第三方登录；Windows 本机后端保持单用户模式，不提供这些页面或 API。

## 用户管理

管理员可以：

- 创建或停用用户；
- 编辑用户名、邮箱等显示资料；
- 重置用户密码；
- 提升或降低管理员权限；
- 撤销该用户的全部客户端会话；
- 查看邮箱、GitHub 绑定和 2FA 状态。

内置 `admin` 不能被停用或降权。调整密码、角色、状态或账号安全设置时，后端会立即撤销旧会话。客户端管理员只访问自己的书架；浏览器管理密码则用于全局运维，两者不能互换。

## 注册策略

自助注册始终要求唯一邮箱。管理员可以分别启用：

| 判断 | 用户需要完成什么 |
| --- | --- |
| 不启用额外判断 | 提交邮箱、用户名和密码 |
| 邮箱验证码 | 先接收并填写一次性验证码 |
| 固定身份牌 | 填写管理员线下提供的身份牌 |
| 两项同时启用 | 邮箱验证码和身份牌必须全部通过 |

保存后立即应用于新的注册请求，不影响已登录用户。SMTP 密码、身份牌和验证码不会在管理响应或日志中回显。

## SMTP 设置

**注册设置** 支持 STARTTLS、SSL 和无认证本地 Relay。按邮件服务商提供的主机、端口、发件地址与认证信息填写；只有受信本地 Relay 才应选择无加密、无认证模式。

验证码具有有效期、错误次数、重发间隔，以及邮箱和来源地址限流。修改 SMTP 密码时按界面选择保留、替换或清除，空字段不会意外擦除既有密钥。

## GitHub Device Flow

1. 在 GitHub 创建 OAuth App；
2. 在 OAuth App 设置中启用 **Device Flow**；
3. 将 Client ID 填入青卷 **注册设置** 并启用 GitHub 登录；
4. 已注册用户登录青卷后，在 **账号安全** 中自行绑定。

青卷不需要保存 Client Secret。用户只应在 `https://github.com/login/device` 输入设备码；GitHub 登录只请求公开身份，不会自动注册本地账号，也不会获得邮箱或仓库权限。

## 与连接 Token 的关系

远程客户端需要先提供实例的连接 Token，再注册或登录用户账号。三类凭据职责不同：

- 连接 Token：控制谁可以访问这台青卷服务；
- 用户会话：标识当前书架和任务的所属用户；
- 管理密码：登录浏览器管理界面。

不要把三者设置成相同值，也不要在日志或公开截图中展示任一凭据。
